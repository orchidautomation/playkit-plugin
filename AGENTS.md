# Repo Agent Instructions

## Product Context

- Purpose: Compile one canonical PlayKit source project into Claude Code, OpenCode, Codex, and Cursor plugin distributions.
- Primary users: PlayKit customers using Clay workflows through supported AI editors.
- Production surface: GitHub release installers and archives generated by Pluxx from `pluxx.config.ts` and canonical source files.

## Workflow

- Use Linear as the source of truth for scoped work.
- Keep implementation work on task branches or worktrees, not directly on main.
- Link PRs back to Linear issue keys.
- Store durable agent artifacts under docs/orchid/.
- Keep temporary/raw agent outputs in .agent-artifacts/.

## Artifact Map

- Brainstorms and PRDs: docs/orchid/brainstorms, docs/orchid/requirements
- Implementation plans: docs/orchid/plans
- To-dos and handoffs: docs/orchid/todos
- Reviews and QA evidence: docs/orchid/reviews, docs/orchid/qa
- Work history and provenance summaries: docs/orchid/history
- Visual plans and recaps: docs/orchid/visual-plans, docs/orchid/visual-recaps
- Durable decisions and reusable lessons: docs/orchid/decisions, docs/orchid/solutions

## Validation

- Required checks: `npx --yes @orchid-labs/pluxx@0.1.36 test` and `PLUXX_COMMAND_JSON='["npx","--yes","@orchid-labs/pluxx@0.1.36"]' node --test tests/opencode-wrapper.test.mjs`.
- Manual QA: inspect all four generated host manifests and run the installed OpenCode wrapper from a parent launch directory with a different selected workspace.
- Deployment/release proof: verify the merged SHA is contained in the public tag, every release asset is present with digests, then reinstall the public OpenCode asset and repeat the parent-launch smoke.

## Release Guardrails

- Keep the trusted release workflow pinned to exact `@orchid-labs/pluxx@0.1.36` and its verified npm integrity.
- Advance the canonical plugin version in `pluxx.config.ts`; generated host manifests and release assets must come from Pluxx, never hand edits.
- This repository intentionally has no root `package.json`. Do not add one for release tooling.
- Preserve `SECURITY_TODO.md` if it exists and keep PlayKit server/product work, secret rotation, unrelated features, and Pluxx PR stack #434-440 out of release-only changes.

## Privacy And Safety

- Do not commit secrets, raw private transcripts, auth files, cookies, API tokens, or browser session data.
- Keep temporary/raw agent outputs in .agent-artifacts/.
